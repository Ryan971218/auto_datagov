# MeanFlow · 含义流转平台

> 数据工程领域的"含义工厂"。让每个数据动作都留下"为什么这么做"的痕迹。

---

## 一句话定位

**AI 是认知助手，人才能拍板。** 每一份治理成果（axiom / SOP / template / flow）都必须从真实问题中结晶、由人工批准、由反馈验证。

---

## 它要解决什么

| 真实场景 | 频率 | 直接损失 |
|---|---|---|
| 财务 GMV 与数仓 GMV 偏差 200 万 | 每月 1-2 次 | 财务月结延期 1 周 |
| 上游改了 schema，下游 dbt 跑挂 | 每周 1-2 次 | 每个事故 4-8 小时 debug |
| 新人入职不知道"GMV 怎么算" | 每次入职 | 平均 2 个月上手 |

> 这些不是"工具不够强"的问题，而是**业务含义在数据系统里没有留下痕迹**的问题。
> MeanFlow 不是"数据治理系统"，是**业务含义流转的基础设施**。

---

## 5 条不能动的原则

1. **数据-含义 gap 是宇宙级的**——不可消除，只能管理。
2. **业务含义必须可追溯**——谁定义、谁修改、影响哪些下游，全部留痕。
3. **AI 只起草，人才能批**——任何 axiom / SOP / template 都必须人工签发。
4. **Wiki 必须自生长**——没有触发器的内容是孤儿条目，必须清理。
5. **反馈驱动修订**——治理成果不是写一次就完，每条记录都可以被打回重做。

详见 [DESIGN.md](./DESIGN.md)。

## 如何贡献

这是一个 **设计先行 / 原型驱动** 的项目，最有价值的贡献方式是：

1. **指出设计漏洞** — 提 Issue，引用 [DESIGN.md](./DESIGN.md) 的具体原则
2. **补充场景** — 在 [SALES_PITCH.md](./SALES_PITCH.md) 里加一个真实故事
3. **改进原型** — 直接改 [index.html](./index.html)（单文件好改），PR 附截图
4. **翻译** — 中英双语化文档和原型

代码风格保持极简：**少废话、多结构、清单优于段落**。
